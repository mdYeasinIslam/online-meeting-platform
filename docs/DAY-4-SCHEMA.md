# Raw temporal schema v1 and proposed Day-5 features

Implementation: `src/@modules/research/types.ts`, `sample.ts`, `frame.ts`, `config.ts`. Machine validation is strict TypeScript runtime validation shared by browser and CLI, not only compile-time types. Unknown fields are rejected throughout imported samples, preventing accidental auth/identity metadata retention. Synthetic schema examples are generated by `tests/helpers/research-fixture.mjs` and are **not real BdSL samples**.

## Sample and bundle

A sample has exactly: schemaVersion (1), id (UUID-v4), vocabularyVersion, labelId, participantId, sessionId, take, startedAt, endedAt, durationMs, stoppedBy, detector, orientation, consent, appVersion, frames and quality. Label text is resolved by the versioned vocabulary reference; the manifest must accompany the dataset. Start/end timestamps are UTC ISO strings; duration and relative frame offsets use a monotonic browser clock. End ISO is start wall-clock plus observed monotonic duration so clock adjustments do not reorder a take. Timer delays may lengthen actual duration and result in rejection; they never invent missing frames.

Detector metadata records `@mediapipe/hands`, installed version `0.4.1675469240`, maxNumHands 2, modelComplexity 1, and configured detection/tracking thresholds. Those thresholds are configuration values, not measured frame confidence. Application version is `day4-1`.

Orientation metadata records inputMirrored false, previewMirrored true, handedness `swap-unmirrored`, and actual camera width/height at take start. Consent has confirmed true, protocolVersion `day4-consent-v1`, and confirmedAt; it contains no participant real identity. Stored quality is advisory and always recomputed on validation/export.

Bundle shape: `{ "schemaVersion": 1, "kind": "bdsl-temporal-landmarks", "samples": [...] }`. No account, cookies, audio, video, thumbnail, IP, hardware device ID, or MediaPipe `Results.image` field is stored.

## Frame representation

Each frame has offsetMs (capture submission time relative to take start), left, right, unassigned, validity. Left/right are nullable observations. Each observation contains exactly 21 `{x,y,z}` landmarks, reportedHandedness (`Left`, `Right` or null), handednessConfidence (score or null), and detectionConfidence (always null). Validity is `{left:boolean,right:boolean}` matching non-null assigned hands. Total left+right+unassigned observations is at most two.

Raw points are the installed API's normalized image coordinates, copied without wrist centering, scale changes, mirroring, resampling or feature extraction. x/y use image dimensions; z is the API's relative depth quantity, not a calibrated world distance. No world-landmark or optional visibility field is retained. The installed API exposes handedness score but no per-hand detection-confidence result, so detectionConfidence is explicitly null.

The legacy MediaPipe Hands output assumes mirrored input. The research detector receives unmirrored video with selfieMode false, so reported Right is assigned to anatomical left and reported Left to anatomical right. Only CSS mirrors the preview/overlay; stored xyz coordinates remain in the source image coordinate system. Scores below 0.8 or missing classification produce unassigned observations. Conflicting observations claiming the same slot both become unassigned; one is never silently substituted for the other. No tracking identity is inferred from nearest position. Frames with no detection contain null/null, an empty unassigned list and false masks. Detector ordering is paired with its corresponding handedness array element.

Confirm left/right on the actual camera before collecting. Virtual/already mirrored cameras may violate the declared assumption. This is a documented convention, not proof of anatomical ground truth. Official reference: [MediaPipe Hands output and handedness](https://chuoling.github.io/mediapipe/solutions/hands.html#multi_handedness); installed API evidence is `node_modules/@mediapipe/hands/index.d.ts`.

## Centralized starting thresholds

All collection and sample-quality constants live in `src/@modules/research/config.ts`:

| Setting | Starting value |
| --- | --- |
| Countdown / capture window | 3000 ms / 4000 ms |
| Target detector rate / UI interval | 15 FPS / 250 ms (state countdown updates at 100 ms) |
| Detector complexity / maximum hands | 1 / 2 |
| Detector detection/tracking thresholds | 0.7 / 0.7 |
| Assigned handedness minimum score | 0.8 |
| Allowed duration | 2000–8000 ms |
| Minimum frames with at least one assigned hand | 8 |
| Missing-or-unassigned frame warning / rejection | >40% / >90% |
| Effective FPS warning / rejection | <5 / <1 |
| x/y tolerance | -0.25 to 1.25 |
| Absolute z tolerance | ≤2 |
| Raw frames per sample | ≤360 |
| Local samples / serialized bundle | ≤100 / ≤20 MiB |
| CLI samples / total input size | ≤3000 / ≤100 MiB |

Coordinate tolerances are permissive engineering guards for near-frame-edge predictions, not learned physical limits. Invalid landmark count, nonfinite values, unsupported schema, invalid IDs/references, extra fields, mismatched masks, unreliable assigned slots, non-monotonic/out-of-window frame timestamps and inconsistent start/end/duration reject samples. No-hand samples reject. A two-hand label warns if both hands are not assigned in at least half its frames. Unassigned observations and capture gaps above one second warn. Duplicate sample IDs reject, and byte-identical xyz trajectories (ignoring time/identity) are screened by a noncryptographic paired hash and flagged for review; this is neither a content signature nor approximate duplicate detection. Identical trajectories block training splits pending review.

Effective FPS is `(N-1)*1000/(lastOffset-firstOffset)` for at least two frames. Missing rate is the fraction of frames with neither left nor right assigned—not the fraction of all possible hand slots. For one-hand signs an empty opposite slot is expected. Rejection and warning reasons remain visible; no sample is silently accepted or discarded. Stored quality includes status, reasons, durationMs, frameCount, validFrames, effectiveFps, missingRatio and unassignedFrames.

## Derived features proposed for Day-5, not implemented or claimed optimal

1. Preserve immutable raw samples and review results. Resolve sign/handedness problems before modelling. Split by participant **before** augmentation or fitting any learned normalization.
2. A basic frame can have 2 × 21 × 3 = 126 xyz features, two hand-validity masks and a sequence/padding mask. This is separate from the existing static 63-feature classifier.
3. Consider subtracting each present hand's wrist for translation and scaling by a defensible palm-distance measure, such as wrist to middle-finger MCP or a median of several wrist-to-MCP distances. Reject/mark near-zero scale; do not divide by arbitrary tiny values. Compare approaches rather than assuming optimality.
4. Wrist-relative features remove global/inter-hand position and some meaningful motion. Preserve/compare additional normalized wrist position, inter-wrist vector, image aspect ratio and perhaps scale as separate features; do not silently erase sign information.
5. Decide whether left-handed mirroring is linguistically valid with qualified reviewers. Mirroring is not automatic augmentation; it can change sign meaning and handedness. Keep any transformed features separate with explicit metadata.
6. Resample by original timestamps to a chosen fixed sequence length (candidate 32 or 64, to be tested). Do not use frame index as time on variable-FPS capture. Interpolate only within short valid spans and do not bridge hand absence or handedness ambiguity as if observed.
7. Missing-hand feature slots may be zeros **only with false validity masks**. Padding uses a separate sequence mask; real rest/no-hand frames remain distinguishable from padded frames. Do not infer arbitrary landmarks for missing hands.
8. Optional velocity uses coordinate delta divided by actual time delta, with zero/invalid mask across missing observations or discontinuities. Compare xyz-only and motion features as experiments.
9. Select and train a small temporal baseline only after sufficient reviewed, consented samples and label coverage exist. Save preprocessing configuration, feature layout, manifest version, exact split IDs, seed, training-only fitted parameters and model artifact together.

Open decisions include vocabulary/sign variants, nonmanual-marker limitations, sample duration, minimum FPS, dominant-hand convention, normalization, resampling length/gap tolerance, masks, augmentation, model family and evaluation strategy. Day-4 offers the collection/validation boundary; it performs none of these training experiments.
